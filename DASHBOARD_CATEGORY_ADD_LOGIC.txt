PART 1: ADDING MAIN CATEGORY - COMPLETE LOGIC
================================================================================

1.1 ACCESSING THE MAIN CATEGORY FORM
-------------------------------------------------------------------------------

Navigation Path:
Dashboard → Categories Tab → Main Categories Tab → "Add Main Category" Button

UI Elements:
- Tab Navigation: Two tabs ("Main Categories" and "Sub Categories")
- Button Location: Top right of Main Categories tab
- Button Text: "Add Main Category" with Plus icon
- Form Type: Modal Dialog (overlay form)

1.2 MAIN CATEGORY FORM STRUCTURE
-------------------------------------------------------------------------------

Form Fields:

FIELD 1: Category Name
- Type: Dropdown Select
- Required: Yes (indicated by asterisk *)
- Options: Only two values
  * "Mens"
  * "Womens"
- Behavior: 
  * User must select from dropdown (no free text input)
  * Dropdown shows only these two options
  * When editing, this field is DISABLED (cannot change name after creation)
- Validation: Only accepts "Mens" or "Womens"
- Helper Text: "Main category must be either 'Mens' or 'Womens'"

FIELD 2: Category Image URL
- Type: Text Input (URL type)
- Required: No (optional field)
- Format: Full URL string (e.g., "https://example.com/image.jpg")
- Placeholder: "https://example.com/image.jpg"
- Purpose: Image displayed on collection page for main category cards
- Helper Text: "Image URL for the category card (used in collections page)"

Form Actions:
- Cancel Button: Closes dialog, clears form, does not save
- Create/Update Button: Submits form and saves to database
  * Text changes based on mode: "Create" (new) or "Update" (editing)
  * Disabled state: Button disabled if Category Name is empty

1.3 MAIN CATEGORY FORM STATE MANAGEMENT
-------------------------------------------------------------------------------

State Variables:
- mainCategoryForm: Object with two properties
  {
    name: string (empty string initially)
    image: string (empty string initially)
  }
- showMainCategoryDialog: boolean (controls dialog visibility)
- editingMainCategory: MainCategory object or null
  * null = Creating new category
  * MainCategory object = Editing existing category

Form Initialization:
- On "Add" button click: Resets form to empty state
  * name: ""
  * image: ""
  * editingMainCategory: null
- On "Edit" button click: Pre-fills form with existing data
  * name: category.name
  * image: category.image || ""
  * editingMainCategory: category object

1.4 MAIN CATEGORY FORM SUBMISSION LOGIC
-------------------------------------------------------------------------------

Step-by-Step Process:

STEP 1: Form Validation (Client-Side)
- Check: Is name field filled?
- If empty: Submit button is disabled (prevention)
- If filled: Proceed to submission

STEP 2: Determine API Endpoint
- Check: Is editingMainCategory null?
  * If null (creating new):
    - URL: '/api/categories/main'
    - Method: 'POST'
  * If not null (editing):
    - URL: '/api/categories/main/{category._id}'
    - Method: 'PUT'

STEP 3: Prepare Request Data
- Extract form values:
  * name: mainCategoryForm.name
  * image: mainCategoryForm.image
- Format: JSON object
  {
    name: string,
    image: string
  }

STEP 4: Send API Request
- Method: POST or PUT (based on editing state)
- Headers: { 'Content-Type': 'application/json' }
- Body: JSON.stringify(mainCategoryForm)
- Endpoint: Determined in Step 2

STEP 5: Handle API Response
- If success (data.success === true):
  * Show success toast notification
    - Title: "Success!"
    - Description: "Main category created successfully" OR "Main category updated successfully"
  * Close dialog (setShowMainCategoryDialog(false))
  * Reset form (clear all fields)
  * Clear editing state (setEditingMainCategory(null))
  * Refresh category list (fetchCategories())
  
- If error (data.success === false):
  * Show error toast notification
    - Title: "Error"
    - Description: data.error message from API OR "Failed to save main category"
    - Variant: "destructive" (red color)

STEP 6: Refresh Category List
- Function: fetchCategories()
- Actions:
  * Fetches all main categories from API
  * Updates mainCategories state array
  * Table automatically re-renders with new/updated category

1.5 SERVER-SIDE API LOGIC FOR MAIN CATEGORY CREATION
-------------------------------------------------------------------------------

API Route: POST /api/categories/main

REQUEST PROCESSING:

STEP 1: Parse Request Body
- Extract: name, image from request body
- Format: JSON object

STEP 2: Validation
- Check: Is name provided?
  * If missing: Return error
    {
      success: false,
      error: 'Category name is required'
    }
    Status: 400 (Bad Request)

- Check: Is name valid?
  * Valid values: "Mens" or "Womens" (case-insensitive)
  * Normalization: Converts to title case
    - Input: "mens" → "Mens"
    - Input: "WOMENS" → "Womens"
    - Input: "Mens" → "Mens"
  * Validation:
    - normalizedName must be either "Mens" or "Womens"
    - If invalid: Return error
      {
        success: false,
        error: 'Main category must be either "Mens" or "Womens"'
      }
      Status: 400

STEP 3: Database Connection
- Connect to MongoDB
- Access collection: 'main_categories'
- Collection name defined in: COLLECTIONS.MAIN_CATEGORIES

STEP 4: Duplicate Check
- Query: Find category with same name
  {
    name: normalizedName
  }
- If exists: Return error
  {
    success: false,
    error: 'Category already exists'
  }
  Status: 400
- If not exists: Proceed

STEP 5: Create Category Document
- Structure:
  {
    name: normalizedName (string: "Mens" or "Womens"),
    image: image || '' (string: URL or empty string),
    createdAt: new Date() (Date object),
    updatedAt: new Date() (Date object)
  }

STEP 6: Insert into Database
- Method: insertOne(newCategory)
- Collection: main_categories
- Returns: Insert result with generated _id

STEP 7: Return Success Response
- Format:
  {
    success: true,
    category: {
      _id: result.insertedId.toString(),
      name: normalizedName,
      image: image || '',
      createdAt: Date,
      updatedAt: Date
    }
  }
- Status: 200 (OK)

ERROR HANDLING:
- Database errors: Return generic error message
- Log error to console for debugging
- Return:
  {
    success: false,
    error: 'Failed to create category'
  }
  Status: 500 (Internal Server Error)

1.6 MAIN CATEGORY DATA STORAGE
-------------------------------------------------------------------------------

Database Collection: main_categories

Document Structure:
{
  _id: ObjectId (auto-generated by MongoDB),
  name: String (required, "Mens" or "Womens"),
  image: String (optional, URL or empty string),
  createdAt: Date (auto-set on creation),
  updatedAt: Date (auto-set on creation and updates)
}

Storage Location: MongoDB database (collection: main_categories)
Persistence: Permanent (until deleted)

2.5 SERVER-SIDE API LOGIC FOR SUB CATEGORY CREATION
-------------------------------------------------------------------------------

API Route: POST /api/categories/sub

REQUEST PROCESSING:

STEP 1: Parse Request Body
- Extract: name, mainCategory, image from request body
- Format: JSON object

STEP 2: Validation
- Check: Are name and mainCategory provided?
  * If missing: Return error
    {
      success: false,
      error: 'Sub category name and main category are required'
    }
    Status: 400 (Bad Request)

STEP 3: Database Connection
- Connect to MongoDB
- Access collections:
  * 'main_categories' (to validate main category exists)
  * 'sub_categories' (to save new sub category)

STEP 4: Validate Main Category Exists
- Query: Find main category with matching name
  Collection: main_categories
  Query: { name: mainCategory }
- If not found: Return error
  {
    success: false,
    error: 'Main category does not exist'
  }
  Status: 400
- If found: Proceed

STEP 5: Duplicate Check
- Query: Find sub category with same name AND same main category
  Collection: sub_categories
  Query:
    {
      name: name,
      mainCategory: mainCategory
    }
- Logic:
  * Same sub category name can exist under different main categories
    Example: "Rider" can exist under both "Mens" and "Womens"
  * Same sub category name cannot exist twice under same main category
    Example: Cannot have two "Rider" subcategories under "Mens"
- If exists: Return error
  {
    success: false,
    error: 'Sub category already exists for this main category'
  }
  Status: 400
- If not exists: Proceed

STEP 6: Create Sub Category Document
- Structure:
  {
    name: name (string: sub category name, e.g., "Rider"),
    mainCategory: mainCategory (string: parent category name, e.g., "Mens"),
    image: image || '' (string: URL or empty string),
    createdAt: new Date() (Date object),
    updatedAt: new Date() (Date object)
  }

STEP 7: Insert into Database
- Method: insertOne(newSubCategory)
- Collection: sub_categories
- Returns: Insert result with generated _id

STEP 8: Return Success Response
- Format:
  {
    success: true,
    subCategory: {
      _id: result.insertedId.toString(),
      name: name,
      mainCategory: mainCategory,
      image: image || '',
      createdAt: Date,
      updatedAt: Date
    }
  }
- Status: 200 (OK)

ERROR HANDLING:
- Database errors: Return generic error message
- Log error to console for debugging
- Return:
  {
    success: false,
    error: 'Failed to create sub category'
  }
  Status: 500 (Internal Server Error)

2.6 SUB CATEGORY DATA STORAGE
-------------------------------------------------------------------------------

Database Collection: sub_categories

Document Structure:
{
  _id: ObjectId (auto-generated by MongoDB),
  name: String (required, sub category name, e.g., "Rider"),
  mainCategory: String (required, parent category name, e.g., "Mens"),
  image: String (optional, URL or empty string),
  createdAt: Date (auto-set on creation),
  updatedAt: Date (auto-set on creation and updates)
}

Relationship:
- mainCategory field stores the NAME of the main category (not ID)
- Links sub category to parent main category via name matching
- Allows filtering: Find all subcategories where mainCategory === "Mens"

Storage Location: MongoDB database (collection: sub_categories)
Persistence: Permanent (until deleted)

7.3 HIERARCHICAL STRUCTURE
-------------------------------------------------------------------------------

Level 1: Main Category

- Stored in: main_categories collection
- Parent of: Sub Categories

Level 2: Sub Category
- Examples: "Rider", "Bomber", "Biker"
- Stored in: sub_categories collection
- Child of: Main Category
- Linked via: mainCategory field (stores parent name)

Relationship Flow:
Main Category ("Mens")
  └─ Sub Category ("Rider") [mainCategory: "Mens"]
  └─ Sub Category ("Bomber") [mainCategory: "Mens"]
  └─ Sub Category ("Biker") [mainCategory: "Mens"]

PART 8: API ENDPOINTS DETAIL
================================================================================

8.1 MAIN CATEGORIES API
-------------------------------------------------------------------------------

GET /api/categories/main
- Purpose: Fetch all main categories
- Method: GET
- Parameters: None
- Response:
  {
    success: boolean,
    categories: MainCategory[] (array of category objects)
  }
- Sorting: Alphabetical by name (name: 1)

POST /api/categories/main
- Purpose: Create new main category
- Method: POST
- Headers: Content-Type: application/json
- Body:
  {
    name: string ("Mens" or "Womens"),
    image: string (optional URL)
  }
- Response Success:
  {
    success: true,
    category: MainCategory object
  }
- Response Error:
  {
    success: false,
    error: string (error message)
  }

8.2 SUB CATEGORIES API
-------------------------------------------------------------------------------

GET /api/categories/sub
- Purpose: Fetch sub categories (optionally filtered)
- Method: GET
- Query Parameters:
  * mainCategory (optional): Filter by main category name
    Example: /api/categories/sub?mainCategory=Mens
- Response:
  {
    success: boolean,
    subCategories: SubCategory[] (array of sub category objects)
  }
- Sorting: Alphabetical by name (name: 1)
- Filtering: If mainCategory provided, only returns matching subcategories

POST /api/categories/sub
- Purpose: Create new sub category
- Method: POST
- Headers: Content-Type: application/json
- Body:
  {
    name: string (sub category name),
    mainCategory: string (parent category name),
    image: string (optional URL)
  }
- Response Success:
  {
    success: true,
    subCategory: SubCategory object
  }
- Response Error:
  {
    success: false,
    error: string (error message)
  }
