- Parsing: Removes "$" and converts to number

4. "name-a-z" - "Name: A to Z"
5. "name-z-a" - "Name: Z to A"
6. "newest" - "Newest First"

11.3 SORTING LOGIC
-------------------------------------------------------------------------------

Implementation Order:
1. Apply all filters first (get filtered products)
2. Then apply sorting to filtered results

Sorting Algorithms:

1. Featured (default):
   - Database products with featured: true come first
   - Then other products
   - Maintains original order within each group

2. Price: Low to High:
   - Extract numeric price: parseFloat(price.replace('$', ''))
   - Sort ascending: Lower prices first
   - Example: $200, $480, $600, $800

3. Price: High to Low:
   - Extract numeric price: parseFloat(price.replace('$', ''))
   - Sort descending: Higher prices first
   - Example: $800, $600, $480, $200

4. Name: A to Z:
   - Sort by product.name alphabetically
   - Case-insensitive
   - Ascending order

5. Name: Z to A:
   - Sort by product.name alphabetically
   - Case-insensitive
   - Descending order

6. Newest First:
   - Database products: Sort by createdAt date (newest first)
   - Static products: Maintain original order
   - If both exist: Database products first (newer)

13.1 MULTI-FILTER BEHAVIOR
-------------------------------------------------------------------------------

Filter Combination:
- All active filters work together (AND logic)
- Product must match ALL active filters to be displayed

  * Product must be:
    - Category: "jackets"

-------------------------------------------------------------------------------

Filter Order (Evaluation):
1. Search Term (first check)
2. Main Category (if specified)
3. Sub Category (if specified, takes priority over category)
4. Category (if subCategory not specified)
5. Size
6. Color
7. Material
8. Price Range
9. Stock (In Stock Only)

Logic:
- Each filter is evaluated in sequence
- If product fails any filter: Excluded immediately
- Only products passing ALL filters are displayed

-------------------------------------------------------------------------------

Function: getActiveFiltersCount()

Counts Active Filters:
- category !== "all": +1
- size !== "all": +1
- color !== "all" AND color exists: +1
- material !== "all" AND material exists: +1
- priceRange !== [0, 1000]: +1 (if min !== 0 OR max !== 1000)
- searchTerm !== "": +1 (if not empty)
- showInStock === true: +1

Display:
- Badge shows count next to "Filters" title
- Badge only visible when count > 0
- Updates in real-time as filters change

PART 14: PRODUCT FILTERING IMPLEMENTATION
================================================================================

14.1 FILTER FUNCTION STRUCTURE
-------------------------------------------------------------------------------

Location: components/shop-product-grid.tsx
Function: filteredProducts (computed from allProducts.filter())

Input: allProducts array (database + static products)
Output: filteredProducts array (matching all active filters)

14.2 FILTER CHECKS (IN SEQUENCE)
-------------------------------------------------------------------------------

CHECK 1: Search Term Filter
- If filters.searchTerm exists:
  * Convert to lowercase
  * Check: product.name.toLowerCase().includes(searchTerm.toLowerCase())
  * If no match: return false (exclude product)

CHECK 2: Main Category Filter (for collection pages)
- If filters.mainCategory exists AND product.source === 'database':
  * Extract: product.mainCategory OR parse from category string (split('/')[0])
  * Check: productMainCategory === filters.mainCategory
  * If no match: return false (exclude product)

CHECK 3: Sub Category Filter (for collection pages)
- If filters.subCategory exists AND product.source === 'database':
  * Extract: product.subCategory OR parse from category string (split('/')[1])
  * Check: productSubCategory === filters.subCategory
  * If no match: return false (exclude product)
- Else if filters.category !== "all":
  * Check: product.category === filters.category
  * If no match: return false (exclude product)

CHECK 4: Size Filter
- If filters.size !== "all":
  * If filters.size === "custom":
    - Check: Product has custom sizes (not in standard sizes list)
    - If no custom sizes: return false
  * Else:
    - Check: product.availableSizes includes filters.size
    - If not included: return false

CHECK 5: Color Filter
- If filters.color exists AND filters.color !== "all":
  * Check: product.color exists
  * Check: product.color.toLowerCase().includes(filters.color.toLowerCase())
  * If no match: return false

CHECK 6: Material Filter
- If filters.material exists AND filters.material !== "all":
  * Check: product.material exists
  * Check: product.material.toLowerCase().includes(filters.material.toLowerCase())
  * If no match: return false

CHECK 7: Price Range Filter
- Extract numeric price: parseFloat(product.price.replace('$', ''))
- Check: productPrice >= filters.priceRange[0] AND productPrice <= filters.priceRange[1]
- If outside range: return false

CHECK 8: Stock Filter
- If filters.showInStock === true:
  * Check: product.source === 'database'
  * Check: product.stock > 0
  * If stock === 0: return false

If all checks pass: return true (include product)

================================================================================
PART 23: EDGE CASES AND SPECIAL BEHAVIORS
================================================================================

23.1 EMPTY RESULTS
-------------------------------------------------------------------------------

Behavior:
- If no products match filters: Empty state shown
- Product grid shows "No products found" message
- User can clear filters to see all products

23.2 MISSING PRODUCT DATA
-------------------------------------------------------------------------------

Database Products:
- If field missing (e.g., no color): Product excluded when that filter applied
- Null/undefined checks in filter logic
- Safe access with optional chaining

Static Products:
- Limited fields available
- May not match filters requiring database fields
- Always pass stock filter (no stock field)

23.3 CASE SENSITIVITY
-------------------------------------------------------------------------------

Search:
- Case-insensitive (converts to lowercase)

Color/Material:
- Case-insensitive (partial match with lowercase)

Category/Size:
- Exact match (case-sensitive values)

23.4 PRICE PARSING
-------------------------------------------------------------------------------

Price Format:
- Expected: "$480" format
- Parsing: Removes "$" and converts to number
- Error handling: parseFloat returns NaN if invalid
- NaN values: May cause filtering issues

25.1 EXAMPLE: FILTERING FOR BROWN LEATHER JACKETS
-------------------------------------------------------------------------------

User Actions:
1. Navigate to /shop page
2. Select Category: "jackets"
3. Select Color: "Brown"
4. Select Material: "Genuine Leather"
5. Set Price Range: [0, 500]
6. Check "In Stock Only"

System Processing:

Step 1: Filters state updated
{
  category: "jackets",
  size: "all",
  color: "Brown",
  material: "Genuine Leather",
  priceRange: [0, 500],
  searchTerm: "",
  sortBy: "featured",
  showInStock: true
}

Step 2: All products evaluated against filters
- Product 1: "Classic Rider Jacket"
  * Category: "jackets" → ✓
  * Color: "Brown" → ✓
  * Material: "Genuine Leather" → ✓
  * Price: $480 → ✓ (within range)
  * Stock: 10 → ✓
  * Result: INCLUDED

- Product 2: "Black Bomber Jacket"
  * Category: "jackets" → ✓
  * Color: "Black" → ✗ (not Brown)
  * Result: EXCLUDED

- Product 3: "Brown Leather Bag"
  * Category: "bags" → ✗ (not jackets)
  * Result: EXCLUDED

Step 3: Filtered products sorted by "featured"
Step 4: Product grid displays matching products

Result:
- Shows only brown, genuine leather jackets
- Price range: $0 to $500
- In stock only
- Sorted by featured status
